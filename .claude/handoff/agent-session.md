# 에이전트 세션 인수인계 (맥 ICD 팀용)

클라우드 세션("YouTube 라이브 학습", 2026-10-26)에서 사용자와 합의한 내용이다. 맥 팀은 이 대화를 보지 못했으므로 여기 적은 것이 전부다. **맥 팀(건축가·디벨로퍼·리테일 MD·마케터·디자이너)과 그 수첩, 팀장 운영법을 본체로 둔다. 갈아엎지 않는다.** 아래는 그 위에 더할 것이다.

## 1. 사용자가 원하는 것 (사용자 말 그대로 요약)

- 사용자 없이도 Claude가 계속 돌아가고, 업무 품질을 "기업화" 수준으로 올리는 것.
- 직원은 "알아서 학습되는 진짜 사람 같은 직원"이어야 한다. 계속 제안하고, 시키면 하루 종일 돈다.
- 직원끼리 **서로 견제**해야 한다. 한 사람 의견에 치우치는 걸 경계한다. 최종 판단은 사용자가 한다.
- 터보, 우창균 같은 사람의 글·영상, 사용자가 던지는 유튜브 링크, 일하면서 받은 교정에서 **직원이 스스로 배운다.**
- **퍼플렉시티처럼 실시간으로 자료를 찾아오는 것**이 중요하다. 특히 현재 법규와 시세.
- 마케팅, 기획, 홈페이지, 인스타 후킹 등 여러 스킬을 최고 품질로 효율적으로.
- 메일과 카카오톡을 뺀 모든 일을 Claude를 통해서 한다.
- 근무 10:00~18:00 (KST). 보고 구조도 여기에 맞춘다. 일요일 밤 보고는 없애고 **매일** 보고로.
- 브랜드 탐색: **하루 최대한 많이 찾고, 직원들이 검토해서 최종 5개**.
- 노션은 하나의 대시보드처럼, 직원들과 서로 연동.

## 2. 판단 기준과 승인 경계 (바꾸지 말 것)

- 사용자의 기준이 교과서보다 우선한다. 충돌하면 사용자에게 양쪽을 보여주고 사용자가 정한다.
- 보고는 한국어, 결론 먼저, **사실 / 추정 / 미확인**을 나눈다.
- 묻지 않고 해도 되는 일: 초안, 조사, 계산, 요약, 노션 기록 추가, 파일 정리.
- **반드시 사용자 승인**: 소장님께 전달, 외부 발송·게시, 숫자·계약 조건이 들어간 문서 확정, 파일·노션 기록 삭제, 노션 기존 결정 기록 수정, 결제.
- 모든 제안서 끝에 5페이지: Program Fit / Business Model / Operation Model / Risk & Alternative / Asset Value Logic.
- 사용자가 스스로 적은 약점: 숫자 검증, 운영 현실, 법규, 임차인 관점. 직원 구성은 이 넷을 매번 외부에서 대신 봐 주도록 짠다.

## 4. 실시간 조사 (퍼플렉시티 역할)

맥은 클라우드와 달리 네트워크 제한이 없을 가능성이 크다(미확인, 첫 실행에서 확인). 확인할 사이트: law.go.kr(국가법령정보센터), eum.go.kr(토지이음), sbiz.or.kr(소상공인 상권정보), rt.molit.go.kr(실거래가), data.go.kr.

도구는 이 순서로 쓴다. 앞 단계로 충분하면 다음으로 가지 않는다.

1. **Claude 기본 웹 검색 + 웹 페이지 열기.** 지금 바로 된다. 검색 요약이 아니라 원문 페이지를 열어 조문·수치를 직접 읽는다.
2. **딥 리서치 스킬.** 여러 출처를 묶은 보고서가 필요할 때.
3. **법제처 Open API.** 조문 원문을 정확히 인용해야 할 때. 무료지만 인증키 신청이 필요하다(사용자가 신청).
4. **Claude in Chrome 확장.** 네이버 부동산, 디스코, 밸류맵처럼 로그인이나 동적 화면이 필요한 곳.
5. **Perplexity MCP.** 1~4로 부족할 때만. 유료 API 키가 필요하고 비용은 미확인. 도입은 사용자 결정.

기록 규칙:
- 법규 = 조문 원문 + 해당 지자체 조례 + 시행일 + 조회일. "개정됐다"만 쓰면 미완료.
- 시세 = 실거래가와 호가 구분 + 조회일.
- 상권 = 출처 + 집계 기간.
- 출처 등급: 원문 / 검색 요약 / 2차 인용. 접근 실패한 곳은 보고 상단에 적는다.
- 미확인은 소장님께 드릴 질문으로 바꾼다.

참고 사례 (클라우드에서 검색 요약으로 확인, 원문 미확인): 주차장법 시행령 2026-08-25 개정, 2026-08-28 시행. 사용승인 5년 경과 · 연면적 1천㎡ 미만 건물 용도변경 시 부설주차장 추가 확보 면제. 근생 → 전용 30㎡ 미만 오피스텔 특례는 2027-12-31까지 신청. 설치기준은 조례로 달리 정할 수 있음. 맥에서 원문 확인 후 건축가 수첩에 등급을 올린다.

## 5. 이미 판정한 외부 도구·글 (다시 검토하지 않는다)

- 가져온 개념: Ruflo의 역할 분담과 반대 검토자, prompt-audit의 "강조어 대신 완료 조건", Duet의 "먼저 챙기고 승인 지점에서 멈춤", Anthropic 마케팅팀의 "만드는 AI와 검사하는 AI 분리", 에이전트 설계법의 "읽기 전용부터, 도구 3~5개, 멈춤 지점".
- 쓰는 것: MarkItDown(PDF·엑셀을 텍스트로), Productivity·Marketing 플러그인(사용자 설치 시), Claude in Chrome.
- 쓰지 않는 것: Ruflo 설치, Basic Memory, SilverBullet, Docmost, WeKnora, security-audit, Graft, Codebase Memory, Agency Agents 230명, OpenMontage, 워터마크 제거, hongik.man 콘텐츠 시스템, Small Business 메일 기능, Duet(한국 미출시).
- 보류: 영상 제작 파이프라인(Royal Mile 홍보·부지 설명 영상 수요가 생기면).
- 앞으로 사용자가 글·도구를 보내면 "적용 / 보류 / 버림" 한 줄 판정과 이유만 준다. 기준은 하나: "소장님께 가는 판단 재료의 정확도를 올리는가."

## 5-1. 이미 노션에 옮겨 둔 맥 팀 기록 (2026-10-26, 클라우드 세션)

맥 팀의 아티팩트를 읽어 노션에 넣었다. 맥 팀은 다음부터 같은 형식으로 직접 쓴다.
- 브랜드 후보 DB: 소싱 1~6회차 카드 25개. 1회차 5개는 상태 "보류"(채민 '별로'), Kakeru·Kettl은 "검토 중"(채민 '좋다'), 나머지 "후보"(판정 대기). 적용 프로젝트 = ICD 자체 브랜드 개발. 출처 칸에 아티팩트 링크.
- 업무일지(생각정리): 소싱 1~6회차 6건(작성자 리테일 MD, 판정 대기 회차는 판단 필요 체크), 아침 카드 10/07~10/26 13건(작성자 팀장, 원문 링크).
- 결정 기록: 브랜드 판정 기준(세 다리) 1건 + MD 예측 4건(미나 페르호넨 상설 2028-10, 차 초콜릿 관세, 서울 트렁크쇼 선금 8건, 다음 소싱 1,000만+ 갈래).
- 직원 DB 수첩 위치: 팀장·마케터는 맥 세션 기록에서 확인한 경로, 나머지는 [추정] — 맥 세션이 실제 경로로 고친다.
- 브랜드 탐색은 이 저장소의 brand-scout(8개 기준 채점)가 아니라 **맥 팀의 brand-sourcing 스킬이 본체**다. 8개 기준은 참고로만. 3절 표 8번은 "비교만 하고 맥 방식 유지"로 바꾼다.

## 6. 첫 실행에서 할 일

1. 이 파일과 `notion-contract.md` 를 읽는다.
2. 노션 연결 상태와 위 사이트 접근 여부를 확인해 보고한다.
3. 3절 표의 2~8번에 대해 "맥 팀에 이미 있는 것 / 새로 넣을 것 / 겹쳐서 선택이 필요한 것" 표를 사용자에게 보여주고 멈춘다.
4. 승인받은 것만 반영하고, 반영 결과를 노션 팀 보고에 "팀 정비 YYYY-MM-DD"(보고자 팀장, 종류 검수)로 남긴다.
