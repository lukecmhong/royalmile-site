# notion-dashboard — 노션 화면 설계 원칙

노션 페이지·DB·보기를 만들거나 고치는 모든 작업 전에 읽는다. learn-source 규칙과 같이 맨 아래 추가만.

### 2026-10-26 · 출처: 외부 조사(matthiasfrank.de Notion Dashboards 101, thomasjfrank.com, Notion 공식 도움말) + 사용자 교정
- [원본 DB] → 원본(백엔드)은 메인 화면에 펼치지 않는다. 메인에는 WORK 메뉴 같은 링크로만 둔다. 메인은 프론트엔드다.
- [메인에 보기를 붙일 때] → 반드시 "지금 내 일"로 필터한다(오늘, 진행 중, 대기, 이번 주). 필터 없이 전체가 나오면 중복이다. 사용자가 "겹친다"고 교정한 사례: 메인에 STUDY 인사이트 전체 목록을 펼친 것.
- [보기 블록 모양] → 데이터 소스 제목을 숨기고(show_data_source_title=false), 기존 대시보드와 같은 콜아웃(아이콘 + 굵은 제목) 안에 넣는다. 맨 아래에 날것으로 이어 붙이지 않는다. 사용자 교정: "UI UX가 이게 뭐야".
- [레이아웃] → ICD 홈은 2단: 왼쪽 탐색(WORK·TOOLS 회색 콜아웃), 오른쪽 작업(인박스 → 오늘 업무일지 → 판단 대기·이번 주 브랜드 2열 카드), 맨 아래 할일·일정 캘린더(사용자가 직접 체크하는 입력 장치이므로 유지).
- [아이콘] → 회색 계열 노션 아이콘 한 가족으로 통일(pencil, hammer, attachment, flag, star …). 이모지 섞지 않는다.
- [같은 개념의 보기가 둘 이상] → 블록을 따로 만들지 않고 한 블록 안의 탭으로 합친다(예: 결정 대기 / 재검토 도래).
- [레코드 대시보드] → 프로젝트 같은 개별 페이지는 그 자체가 대시보드다. 관련 DB는 양방향 관계로 연결해 프로젝트 페이지 안에서 결정 기록·브랜드 후보·회의기록이 보이게 한다.
- [템플릿 행] → "프로젝트 템플릿"처럼 실제 항목이 아닌 행은 보기 필터로 숨긴다. 지우지 않는다.
- [작업 순서] → 노션 화면을 바꾸기 전에 대상 페이지를 fetch로 읽고, 기존 구조(콜아웃·컬럼·구분선)를 그대로 따라 끼워 넣는다.

### 2026-10-26 · 출처: 홈 재배치 작업 중 확인
- [replace_content로 기존 블록을 옮길 때] → 한 번에 순서가 안 맞는 경우가 있다(ICD 홈, ICD 팀 두 번 재현). 적용 직후 fetch로 순서를 확인하고, 틀리면 같은 내용을 한 번 더 적용한다. 두 번째에 맞았다.
- [할 일 진행률] → 프로젝트마다 "프로젝트 과정" DB가 따로 있어 프로젝트 DB에서 롤업할 수 없다. 할일·일정 219건 중 프로젝트에 연결된 것은 0건(2026-10-26 조회). 진행률을 원하면 과정 DB를 하나로 합치는 결정이 먼저다(사용자 승인 사항).
- [API로 못 하는 것] → 보기 탭 순서 변경, 보기 삭제, 캘린더 주간 보기 전환, 버튼 블록. 사용자에게 클릭 위치를 안내한다.
- [홈 구성 확정본] → 위: 5칸 메뉴(업무·판단·기록·지식·TOOLS, 회색 콜아웃) → 오늘 브리핑(팀 보고, 종류 아침 브리핑, 오늘) → 숫자 4칸(남은 할 일, 진행 중 프로젝트, 판단 대기, 팀이 넘긴 일) → 2단(왼쪽 할 일·프로젝트 탭 / 오른쪽 오늘 업무일지·판단 대기·이번 주 브랜드) → 캘린더.

### 2026-10-26 · 출처: 사용자 스크린샷 교정 + 외부 조사(matthiasfrank.de 2026-06, thebricks.com)
- [숫자 카드(number chart)] → 노션 링크드 차트는 툴바와 "모두 세기" 라벨 때문에 한 줄에 화면 1/3을 먹는다. 숫자가 아래 목록(늦음 탭, 판단 대기)과 중복이면 넣지 않는다. 사용자 화면에서 확인: 4칸이 12·2·0·0을 보여주려고 300px를 씀. 제거함.
- [작은 대시보드 여러 개 > 큰 대시보드 하나] → matthiasfrank 2026 가이드. 홈은 "오늘 할 것"만, 팀 사무실·프로젝트 페이지는 각자 대시보드.
- [보고 DB를 따로 만들지 않는다] → 사용자 결정: 업무일지(생각정리)에 직원도 쓴다. 같은 개념(일지·보고)을 두 DB로 나누면 중복. 작성자 관계·판단 필요 체크박스를 기존 DB에 더하는 쪽이 맞다.
- [진행률] → 프로젝트 과정 DB를 합치지 않고, 업무 요청(팀 업무) 상태 롤업(percent_per_group)으로 뽑는다. 기존 기록을 옮기지 않는다. 막대 표시는 API로 못 켠다(사용자가 속성 편집 → 표시 "막대").
- [replace_content와 링크드 뷰] → 링크드 뷰 블록도 "database" 로 세어 삭제 보호에 걸린다. 내가 만든 빈 보기 블록이면 allow_deleting_content로 진행하되 보고에 적는다. 원본 DB는 절대 이 방식으로 지우지 않는다.
- [CLEAR FILTER] → advancedFilter만 지운다. 보기에 simpleFilters(빠른 필터)가 남아 있으면 CLEAR QUICK FILTER "속성" 으로 따로 지운다.
