# 부지 검토 파이프라인

이 스킬을 실행하는 메인 세션이 **비서** 역할이다. 직접 판단하지 않고, 직원들을 순서대로 호출하고, 결과를 이어 붙이고, 노션에 기록한다.

## 0. 접수

- 입력에서 주소 / 건물 / 면적 / 현재 용도 / 사용자가 이미 정한 업종(있으면) / 검토 목적(매입 검토 / 임차 검토 / 클라이언트 제안)을 추린다. 없는 항목은 "미제공"으로 두고 진행한다. 사용자에게 되묻는 것은 주소가 아예 없을 때뿐이다.
- 노션이 연결되어 있으면 같은 주소나 프로젝트명을 검색해 과거 검토 기록을 읽고, 있으면 `과거 검토 있음` 으로 표시해 기획자에게 넘긴다.
- `.claude/knowledge/boss-feedback.md` 를 읽어 이번 검토에서 반드시 확인할 항목을 뽑는다.

## 1. 조사 (병렬 3명)

`researcher` 에이전트를 **세 번 동시에** 호출한다. 각각 브리프를 지정한다.

- A 상권 데이터: 주소, 반경, 필요한 지표
- B 법규·시세: 주소, 지번(알면), 현재 용도, 검토 중인 용도
- C 사례·경쟁: 주소, 검토 중인 프로그램 후보(사용자가 정했으면 그것, 아니면 "미정"), 유사 사례 범위

세 보고서를 그대로 보관한다. 요약하지 않는다. 기획자는 원문을 받는다.

## 2. 판단

`planner` 에이전트에 조사 보고서 3개 + 접수 정보 + 과거 검토 기록을 넘긴다. 7가지 질문에 답한 제안과 "미리 인정하는 약점 3가지"를 받는다.

## 3. 반론 (병렬 3명)

기획자 제안 + 조사 보고서 3개를 `reviewer-developer`, `reviewer-architect`, `reviewer-operator` 에 **동시에** 넘긴다. 세 심사위원은 서로의 결과를 보지 않는다 (독립 반론).

## 4. 재답변

세 반론을 모아 `planner` 를 다시 호출한다. 반론마다 "수용(안 수정) / 반박(근거) / 미해소(인정)" 중 하나로 답하게 한다. 조용히 빼먹는 것을 막기 위해 반론 번호를 전부 나열한 표를 요구한다.

심사위원끼리 결론이 어긋나는 지점(예: 디벨로퍼는 찬성, 운영자는 못 버팀)은 기획자가 어느 쪽을 택했는지와 이유를 따로 적게 한다. 이 충돌은 결정 메모에 그대로 실린다. 숨기지 않는다.

## 5. 결정 메모 작성

메인 세션이 아래 형식으로 1장을 쓴다. 소장님께 드리는 문서다.

```
# 부지 검토 — [주소 / 프로젝트명]   (검토일)

## 한 줄 결론
## 왜 이 부지인가 (또는 왜 아닌가)
## 누가 여기까지 오는가
## 시장이 아직 반영하지 못한 변화
## 제안 프로그램과 운영 구조 (1안 + 대안)
## 숫자 (확보 / 미확보, 손익분기 역산 요약)
## 주요 리스크와 실패 시 대체 용도
## 심사위원 반론과 처리 (표: 반론 / 수용·반박·미해소)
## 심사위원 간 충돌 (있으면)
## 법규·시세 확인 상태 (원문 / 검색 요약 / 미확인)
## 판단 부탁드릴 사항 (소장님께)
## 시공팀에 넘길 질문
```

## 6. 검수

결정 메모 + 조사 보고서 + 반론 + 재답변 전부를 `auditor` 에 넘긴다. "보류"면 사유대로 고친 뒤 **한 번 더** 감사자에게 보낸다. 두 번째도 보류면 사용자에게 사유와 함께 멈춘다. 세 번 이상 돌리지 않는다.

## 7. 기록

- 노션 연결 시: 결정 기록 DB에 한 건 추가 (대상, 한 줄 결론, 핵심 근거, 예측, 재검토일 = 6개월 뒤, 상태 = 검토 완료). 결정 메모 전문은 해당 프로젝트 페이지 하위에 저장.
- 노션 미연결 시: 결정 메모를 `/tmp` 가 아닌 스크래치 폴더에 저장하고 사용자에게 파일로 전달한다. 노션 기록은 "미기록"으로 보고한다.
- 각 직원이 남긴 `[학습 후보]` 를 모아 사용자에게 보여주고, 사용자가 고른 것만 `learn-source` 스킬 절차로 해당 knowledge 파일에 추가한다. 임의로 추가하지 않는다.

## 보고

사용자에게는 결정 메모 전문 + 감사자 판정 + 학습 후보 목록만 보여준다. 중간 산출물은 요청 시 제공한다.

## 승인 경계

- 이 파이프라인은 조사·판단·기록까지 혼자 한다.
- 소장님께 전달, 외부 발송, 노션의 기존 결정 기록 수정·삭제는 하지 않는다. 사용자가 한다.

## 비교 검토일 때

후보지마다 0~6을 각각 돌리고, 마지막에 비교표(입지 성격 / 제안 프로그램 / 손익분기 / 치명 리스크 / 심사위원 판정 3개 / 한 줄 결론)를 만든 뒤 감사자에게 한 번 더 보낸다.
