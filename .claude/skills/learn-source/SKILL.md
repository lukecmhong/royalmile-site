# 학습 파이프라인

직원(에이전트)은 스스로 배우지 않는다. **이 스킬이 knowledge 파일에 쓴 것만** 다음 출근부터 적용된다. 그러므로 적는 문장은 요약이 아니라 "다음부터 X 상황에서 Y를 본다" 형태여야 한다.

## 입력 유형

| 유형 | 예 | 처리 |
| --- | --- | --- |
| 링크 | 유튜브, 기사, 브런치 | 본문·자막을 가져온다. 이 환경에서 유튜브가 막히면 사용자에게 자막 붙여넣기를 요청한다 |
| 인물·채널 | "우창균", "유정수", 특정 채널명 | 공개된 글·영상을 검색해 최근 10건 안팎을 읽는다. 노션 인사이트 DB에 이미 정리된 것이 있으면 먼저 읽고 중복을 피한다 |
| 문서 | PDF, 덱, 보고서 | 텍스트로 변환해 읽는다 |
| 교정 | 사용자가 결과를 고친 내용 | 원문 산출물과 고친 내용의 차이에서 원칙을 뽑는다 |
| 소장님 피드백 | 회의 중 지적 | `boss-feedback.md` 에 우선 기록 |

## 1. 읽기

원문을 읽고 **사실 / 저자의 주장 / 저자의 사례** 로 나눈다. 저자가 누구인지(실무자, 강사, 판매자)를 적는다. 판매 목적 콘텐츠면 그 사실을 적고, 주장 중 근거 있는 것만 남긴다.

## 2. 원칙 추출

주장을 "조건 → 판단" 형태의 문장으로 바꾼다.

- 나쁜 예: "상권보다 건물이 중요하다는 내용"
- 좋은 예: "브랜드형 콘셉트(공간 경험이 브랜드 인상에 기여하는 업종)는 S급 상권의 2층보다 B급 상권의 단독 건물을 우선 검토한다. 근거: 유정수, 피크엔드 법칙 + 단독 건물의 파사드 노출."

원칙마다: 조건, 판단, 근거(출처·저자·날짜), 확신 수준(저자 주장 / 사례로 뒷받침 / 데이터로 뒷받침), 적용 직원.

## 3. 충돌 검사

기존 knowledge 파일과 스킬(`space-planning-strategy`, `trade-area-analysis`)의 원칙과 **어긋나는지** 본다.
- 어긋나지 않음 → 추가
- 어긋남 → 추가하지 않고 사용자에게 양쪽을 나란히 보여준다. 어느 쪽을 택할지는 사용자가 정한다. 사용자가 정하면 기존 원칙에 "(2026-xx 이후 변경: …)" 을 달고 새 원칙을 쓴다. 기존 문장은 지우지 않는다.

사용자의 기준은 교과서보다 우선한다. 새 자료가 교과서적이고 사용자 기준과 충돌하면 기본값은 사용자 기준 유지다.

## 4. 배분

원칙을 직원별로 나눈다. 한 원칙이 여러 직원에게 가도 된다.

- 입지·프로그램·고객 정의 → `planner.md`
- 데이터 출처·수치 주의 → `researcher.md`
- 사업성·자본·exit·권리 → `reviewer-developer.md`
- 법규·건축 조건·공사비 → `reviewer-architect.md`
- 운영·임차인·손익 기준값 → `reviewer-operator.md`
- 반복 오류 유형 → `auditor.md`
- 소장님 지적 → `boss-feedback.md`

## 5. 기록

각 knowledge 파일의 **맨 아래에 추가**한다. 기존 내용을 고치거나 지우지 않는다. 형식:

```
### YYYY-MM-DD · 출처: [저자/링크/교정]
- [조건] … → [판단] … (근거: …, 확신: 저자 주장 / 사례 / 데이터)
```

노션이 연결되어 있으면 인사이트 DB에도 한 건 추가한다 (제목, 출처, 핵심 원칙 3~5개, 적용 직원). 사용자 노션의 기존 인사이트 형식("(유정수) …" 제목 패턴)을 따른다.

## 6. 보고

```
## 읽은 것 (출처, 저자 성격)
## 추출한 원칙 (조건 → 판단, 적용 직원)
## 기존 원칙과 충돌 (있으면, 사용자 결정 필요)
## 기록한 위치
## 기록하지 않은 것과 이유 (근거 부족, 판매 목적, 중복)
```

## 월 1회 정리

knowledge 파일이 길어지면(각 150줄 초과) 사용자에게 "스킬 본문으로 승격할 원칙"을 제안한다. 승격은 `skill-creator` 스킬로 하고, knowledge 파일의 해당 줄에 "(스킬 반영됨)" 을 단다. 승격도 사용자 승인 후에만 한다.

## 금지

- 원문을 통째로 복사해 넣지 않는다. 원칙 문장만.
- 사용자 기준과 충돌하는 원칙을 임의로 덮어쓰지 않는다.
- 링크를 열지 못했는데 열었다고 쓰지 않는다. 못 열면 "접근 실패, 자막·본문 붙여넣기 요청" 으로 끝낸다.
